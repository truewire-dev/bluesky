# Bluesky, typed

A typed, validated, async Python client for [Bluesky](https://bsky.app)'s public AT Protocol API: profiles, posts, threads, feeds, the follow graph, handle resolution, and the Jetstream firehose of everything happening on the network. Generated by [Truewire](https://truewire.dev) from a spec of what the API puts on the wire, so every response is checked against the shape the API recorded, not the shape someone remembered.

No account and no key. Every call goes to the public AppView at `public.api.bsky.app`, which answers these endpoints for anyone, rate-limited by IP.

## Install

Not on PyPI yet; install from the repository:

```sh
pip install git+https://github.com/truewire-dev/bluesky
```

The import name is `bluesky`, and the distribution is `truewire-bluesky`. Python 3.11 or newer.

## Use

```python
import asyncio

from bluesky import Bluesky


async def main() -> None:
  async with Bluesky.new() as client:
    profile = await client.actor.get_profile('bsky.app')
    print(profile['handle'], profile['did'])
    print(profile.get('followersCount'), 'followers ·', profile.get('postsCount'), 'posts')
    feed = await client.feed.get_author_feed(
      actor='bsky.app', limit=3, filter='posts_no_replies'
    )
    for entry in feed['feed']:
      post = entry['post']
      print(post['indexedAt'].date(), '|', post['record']['text'][:48])


asyncio.run(main())
```

```text
bsky.app did:plc:z72i7hdynmk6r22z27h6tvur
4180352 followers · 611 posts
2026-09-05 | Custom feeds are now easier to find from the
2026-09-02 | A few fixes for video playback on Android sh
2026-08-28 | We're hiring a protocol engineer. Details in
```

Every method is typed from the request the API documents (`filter` is a `Literal` of the four values the lexicon lists, `limit` an `int` with the documented range in its docstring), and returns a `TypedDict` validated against the recorded wire shape. Timestamps come back as `datetime`: `indexedAt` and `createdAt` parse from RFC 3339, Jetstream's `time_us` from Unix microseconds. `validate=False` on a call returns the parsed body as it came, typed `Any` — which is how you reach the parts of a post record or a thread the schema does not name.

### The firehose

Jetstream is a WebSocket that pushes every commit, identity change and account status change on the network as JSON. The filter travels in the connection URL, so each subscription is its own socket:

```python
import asyncio

from bluesky import Bluesky


async def watch_posts() -> None:
  async with Bluesky.new() as client:
    async with client.jetstream.events(wanted_collections=['app.bsky.feed.post']) as stream:
      async for event in stream:
        commit = event.get('commit')
        if commit is None or commit['operation'] != 'create':
          continue
        post = commit.get('record', {})  # any collection's record, so a plain map
        print(event['time_us'].strftime('%H:%M:%S'), post['text'][:44])


asyncio.run(watch_posts())
```

```text
12:31:04 finally got the sourdough starter going
12:31:04 this is the third time this week the train h
12:31:05 hot take: the second album is better
```

Pass `cursor=` a `datetime` to replay from an instant instead of starting at now; Jetstream keeps a bounded backlog, and a cursor older than it starts from the oldest event kept.

### The client's shape

| Method | XRPC | What it answers |
| --- | --- | --- |
| `client.actor.get_profile(...)` | `app.bsky.actor.getProfile` | One account's profile, with follower, follow and post counts |
| `client.actor.get_profiles(...)` | `app.bsky.actor.getProfiles` | Up to 25 profiles in one call |
| `client.actor.search_actors(...)` | `app.bsky.actor.searchActors` | Accounts matching a query, paged |
| `client.feed.get_author_feed(...)` | `app.bsky.feed.getAuthorFeed` | An account's posts and reposts, paged |
| `client.feed.get_feed(...)` | `app.bsky.feed.getFeed` | A custom feed, through its generator, paged |
| `client.feed.get_post_thread(...)` | `app.bsky.feed.getPostThread` | A post with its ancestors and replies |
| `client.feed.get_posts(...)` | `app.bsky.feed.getPosts` | Up to 25 posts by AT URI |
| `client.feed.search_posts(...)` | `app.bsky.feed.searchPosts` | Full-text post search, paged |
| `client.graph.get_followers(...)` | `app.bsky.graph.getFollowers` | Who follows an account, paged |
| `client.graph.get_follows(...)` | `app.bsky.graph.getFollows` | Who an account follows, paged |
| `client.identity.resolve_handle(...)` | `com.atproto.identity.resolveHandle` | The DID a handle currently points at |
| `client.jetstream.events(...)` | `jetstream2.us-east.bsky.network` | Every repository event on the network |

The eleven XRPC methods share one host and one connection pool; Jetstream opens a socket per subscription.

### Paging

Six of the endpoints answer a page at a time and hand back a cursor. Each one has a `_paged` twin that walks it: awaited it flattens every page, iterated it yields one page's rows at a time, and `pages()` gives each page with the cursor on either side of it, so a walk can be checkpointed and resumed.

```python
from bluesky import Bluesky


async def everyone_following(actor: str) -> None:
  async with Bluesky.new() as client:
    walk = client.graph.get_followers_paged(actor=actor, limit=100)
    async for page in walk.pages():
      for follower in page.rows:
        print(follower['handle'])
      if page.next is None:
        break
```

### What is not here

These twelve are what the public AppView answers without credentials. The authenticated half of the API — writing posts, following accounts, reading notifications, everything on `bsky.social` that needs a session — is a different client and not wrapped here. `Bluesky.new(access_jwt=...)` takes a token you already hold and sends every call to `bsky.social` instead, which fills in the viewer's own state on a profile or a post; it does not add any endpoint.

## Recordings

Every endpoint carries the request half of at least one example, the exact parameters the tests and the recording script replay. The response halves are recorded from the live API through this same generated client, so a recording is the wire body the client saw and the response types are proven against it, never written by hand. The machine this client was written on could not reach `bsky.app` or `bsky.network`, so the recordings are made on a runner.

Two of the examples name one post by AT URI, and a post can be deleted: `feed.get_post_thread` then answers 400, and `feed.get_posts` answers 200 with an empty array, which records as happily as a full one and proves nothing. [`packages/python/test/refresh_post_examples.py`](packages/python/test/refresh_post_examples.py) runs before anything is captured, checks that the pinned post is still there and still has replies, and repoints both examples at a live one when it is not. The tests read the URI from the example rather than from a constant, so a repair is not a failure.

- [`packages/python/test/recapture.sh`](packages/python/test/recapture.sh) re-records everything. Run it locally with network access, or through the [Record workflow](.github/workflows/record.yml) (Actions, "Record", run workflow), which records on a runner, pushes the new responses to a `record/<run id>` branch and opens a pull request for it. Opening it needs the repository setting "Allow GitHub Actions to create and approve pull requests" (Settings, Actions, General); without it the branch is still pushed and the job summary links to it.
- The XRPC calls are recorded with `truewire capture`, all but the one that needs a session. Jetstream is not a request and a reply, so it is recorded by subscribing for ten seconds through the same client and keeping what the firehose pushed ([`packages/python/test/record_jetstream.py`](packages/python/test/record_jetstream.py)).
- An endpoint without a recorded response says so on the endpoint itself, with the reason; the recording script drops that declaration the moment a response lands. The CI job "Every endpoint has a recording" is a required check: an endpoint arrives with a recording, or with a declaration of why it cannot have one.
- `feed.search_posts` is the one endpoint that will keep its declaration: the public AppView answers `app.bsky.feed.searchPosts` with HTTP 403 to a caller without a session, where it answers the other ten to anyone. The recording script skips it rather than failing on it every run, and its schema stays what the lexicon says rather than what the wire showed.
- Tests replay the recordings through the client against `truewire mock`, which serves them over real HTTP and a real WebSocket; nothing in the tests touches the network. Until a recording exists, its test skips and says why.

```python
from bluesky import Bluesky


async def against_the_mock(http: str, ws: str) -> None:
  # The mock answers a request that matches a recording exactly; these are the recorded
  # parameters, and the WebSocket replays the events the firehose pushed.
  async with Bluesky.new(base_url=http, ws_url=ws) as client:
    print((await client.identity.resolve_handle('bsky.app'))['did'])
    async with client.jetstream.events(wanted_collections=['app.bsky.feed.post']) as stream:
      async for event in stream:
        print(event['kind'], event['did'])
```

The gates that run on every pull request: `truewire check` (the spec against its own rules and every recording against its schema), `truewire standards`, the generated code being current, pytest, pyright over [`packages/python/test/typing_usage.py`](packages/python/test/typing_usage.py), ruff. Every code block in this file is type-checked against the package.
